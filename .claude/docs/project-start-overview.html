RuoYi-Plus 项目全景

一套「Spring Boot 4 + Vue 3」的全栈中后台工程：后端基于 RuoYi-Vue-Plus 6.X（org.dromara）， 前端是基于 vben 5.7 重构的 bell-plus 单仓应用，数据库为 PostgreSQL。 当前业务开发集中在 WMS 仓储管理模块。

后端 6.0.0 · Spring Boot 4.1.0 JDK 21 数据库 PostgreSQL 前端 bell-plus · Vue 3.5.40 包管理 pnpm 11 端口 5666 → 8080

新增一个 WMS 子模块的固定套路

  1. 用 ruoyi-gen 生成骨架

    生成 Controller / Service / Mapper / BO / VO / 前端页面（近期生成器模板已支持模态框类型、树形数据弹窗）。

  2. 执行菜单 SQL

    位于 ruoyi-wms/src/main/resources/sql/*Menu.sql，执行后后台出现菜单与按钮权限。

  3. 定制翻译与联动

    外键名称用 @Translate 翻译；库区→仓库、储位→库区等做级联选择（前端已有联动实现可参考）。

  4. 补前端导入/导出弹窗

    各模块已统一补全导入弹窗，复制现有实现即可。

环境搭建

从零到两个服务跑起来，大约半小时。数据库与 Redis 需先向同事确认可用实例。

  1. 准备基础环境

    JDK 21 · Maven 3.8+ · Node 22.18+/24 · pnpm 11（npm i -g pnpm@11）· PostgreSQL 14+ · Redis 6+

  2. 初始化数据库

    新建库 ruoyi-6.x，按顺序执行 RuoYi-Vue-Plus/script/sql/postgres/ 下的 postgres_ry_vue.sql → postgres_ry_ai.sql → postgres_ry_job.sql → postgres_ry_workflow.sql， 再执行 ruoyi-wms 各模块的 *Menu.sql。

  3. 创建 application-local.yml（关键）

    Maven 默认激活的 profile 是 local，而 application-local.yml 在 .gitignore 中、不入库 —— 新环境需要参照 application-dev.yml 手工创建，填入真实的 PostgreSQL / Redis 地址与密码。 团队实际连接：PG 与 Redis 均在内网 192.168.30.221（端口 5432 / 6379），找同事要现成文件最快。

  4. 启动后端

    cd RuoYi-Vue-Plus && mvn spring-boot:run —— 不带 -P 参数时默认就是 local 环境。 服务起来后访问 http://localhost:8080、监控台 http://localhost:9090/admin。

  5. 启动前端

    cd bell-plus && pnpm install && pnpm dev —— 必须 pnpm，preinstall 里 only-allow pnpm 会拦截 npm/yarn。访问 http://localhost:5666。

开发约定

三层架构 + 统一响应 + 注解式横切能力，新代码务必与既有风格一致。

三层架构与包结构

org/dromara/<module>
controller/   # @RestController，只做参数校验与编排
service/      # 接口 + impl/ 实现，业务逻辑都在这
mapper/       # MyBatis-Plus Mapper，复杂 SQL 走 XML
domain/       # 实体；bo/ 入参、vo/ 出参

RESTful 路径约定

操作方法路径
分页查询GET/list
获取详情GET/{id}
新增POST/
修改PUT/
删除DELETE/{ids}
导出POST/export

高频注解

横切能力一律注解声明
@SaCheckPermission("wms:warehouses:list")   # 权限
@Sensitive(strategy = SensitiveStrategy.PHONE)   # 脱敏
@Translate(table = "sys_user", result = "nickName") # 字段翻译
@Idempotent(key = "xxx", expire = 5000)          # 幂等
@Cacheable(value = "sysUser", key = "#userId")    # Redisson 缓存

所有接口返回统一包装 R<T>（code 200 为成功），分页返回 TableDataInfo<T>；前端已封装对应解包逻辑，不需要手动判断。

常见问题与重要提醒

新人最容易踩的坑都集中在这里，开工前花两分钟读完。

⚠ 根目录 CLAUDE.md 描述的是另一个项目形态，以本页为准

CLAUDE.md 写的是「RuoYi-Plus-UniApp + Element Plus + MySQL + plus.ruoyi 包名 + UniApp 移动端」，但仓库实际是 RuoYi-Vue-Plus 6.X（org.dromara 包名）+ bell-plus（antdv-next）+ PostgreSQL，且没有移动端目录。 参考文档时以 pom.xml、pnpm-workspace.yaml 和本页为准，建议尽快更新 CLAUDE.md 避免误导后续接手的人（和 AI）。

⚠ docker-compose.dev.yml 里的 MySQL 与实际不符

dev compose 起的是 MySQL 8.0.42，但后端实际连接 PostgreSQL。若要用 compose 起本地中间件，需要自行替换为 PG 容器； 根目录另有 deploy-ruoyi.sh / docker-build.sh 等部署脚本，使用前先核对数据库类型。

⚠ application-local.yml 的密码已泄露过，建议更换

该文件虽已加入 .gitignore，但历史提交中出现过真实 Redis 密码。它只应放在本地、绝不入库；更稳妥的做法是直接改掉已泄露的密码。

✱ 前端只能用 pnpm

bell-plus 的 preinstall 钩子是 npx only-allow pnpm，npm / yarn 安装会被直接拦截。Node 版本需 ^22.18.0 或 ^24。

✱ 默认 profile 是 local 不是 dev

pom.xml 中 <activeByDefault> 指向 local。裸跑 mvn spring-boot:run 加载的是 application-local.yml —— 文件不存在时连接信息全为空，后端起不来但报错不明显，先确认这个文件存在。

✱ 如果确实要用 Docker MySQL：中文乱码预防

MySQL 容器必须配置 utf8mb4（my.cnf 的 client/mysql/mysqld 三段 + 后端 UTF-8 encoding + Dockerfile 的 -Dfile.encoding=UTF-8），否则中文会存成 Latin1 乱码。修复 SQL 与完整根因分析见根目录 CLAUDE.md「MySQL 中文乱码预防」一节。
